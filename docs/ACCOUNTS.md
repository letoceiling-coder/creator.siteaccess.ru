# Аккаунты, токены и админка

Дата: 2026-11-18. Код: `server/api/accounts.mjs`, `auth.mjs`, `routes-auth.mjs`, `routes-admin.mjs`, `cli.mjs`; интерфейс — `src/features/auth`, `src/pages/studio/auth-screens.tsx`, `src/pages/admin/admin-page.tsx`.

## Вход

| Способ | Как работает |
| --- | --- |
| Почта и пароль | Регистрация на `/login`. Пароль хранится как scrypt-хэш. Защита от перебора: 10 попыток входа за 15 минут и 5 регистраций в час с одного IP |
| Яндекс ID | OAuth 2.0, `/api/auth/yandex/start` → callback `/api/auth/yandex/callback` |
| VK ID | OAuth 2.1 с PKCE, `/api/auth/vk/start` → callback `/api/auth/vk/callback` |
| Telegram и MAX на сайте | Вход через бота: сайт открывает бота со ссылкой `?start=login_КОД`, бот присылает кнопку «Подтвердить вход», браузер ждёт подтверждения и получает сессию. Сессию получает только браузер, начавший вход (метка в cookie), код живёт 5 минут и срабатывает один раз. Кнопка появляется после «Настроить бота» в админке |
| Мини-приложения Telegram и MAX | Вход сам, по подписанному `initData` (HMAC с ключом «WebAppData»). Ссылка-приглашение: `start_param=ref_КОД` |

Ключи интеграций задаются в админке (раздел «Интеграции», там же пошаговая справка и готовые адреса для копирования). Секреты хранятся только на сервере, в ответах API — маска `••••abcd`. Сессия — cookie `cs_session` (HttpOnly, Secure, SameSite=Lax, 30 дней). Изменяющие запросы с чужих сайтов отклоняются по заголовку Origin.

Боты (`server/api/bots.mjs`, админка → «Интеграции» → «Состояние бота» / «Настроить бота»):

- **Telegram** — запросы к Bot API с сервера идут через tor (`TELEGRAM_PROXY=http://127.0.0.1:8118`, прямой доступ к api.telegram.org с хостинга закрыт). «Настроить бота» ставит вебхук `/api/bots/telegram/webhook` с секретом, кнопку мини-приложения `/telegram` и команду /start.
- **MAX** — API `platform-api.max.ru`, токен в заголовке Authorization. Новый домен `platform-api2.max.ru` требует корневого сертификата Минцифры на сервере — пока не установлен. «Настроить бота» подписывает вебхук `/api/bots/max/webhook` с секретом. Если у бота уже есть вебхуки других сайтов, админка предупреждает: сообщения будут приходить всем.
- Мини-приложения: сайт загружает библиотеки `telegram-web-app.js` / `max-web-app.js` на `/telegram` и `/max`; подписанные данные запуска также читаются из фрагмента адреса. Проверка подписи `initData` MAX совпадает с Telegram (сверено с dev.max.ru/docs/webapps/validation).

## Токены

- У каждого пользователя свой баланс; списания и начисления записываются в журнал (`ledger`), баланс не уходит в минус.
- Стоимость (по умолчанию): фотосессия 10, видеосюжет 30, оживление 5 с — 8, 10 с — 15. Меняется в админке, раздел «Цены и бонусы».
- Токены списываются при постановке задачи и **возвращаются** при ошибке генерации или отмене.
- Бонусы (по умолчанию): регистрация 30; **бесплатно в сутки 10 — только при нулевом балансе**, раз в сутки по Москве; другу по приглашению 10 сразу; пригласившему 20 — когда друг создаст первую успешную работу (защита от накрутки фиктивными регистрациями).
- Генерация доступна только вошедшим; одновременно — до 2 задач на пользователя.

## Тарифы и оплата

Пакеты токенов создаются и редактируются в админке (название, токены, цена, метка, порядок, показ). Пользователь выбирает тариф в кабинете и платит на странице платёжной системы:

| Система | Как подтверждается оплата |
| --- | --- |
| **ЮKassa** (API v3) | Уведомление на `/api/payments/yookassa/webhook`; телу не доверяем — статус и сумма перепроверяются запросом `GET /v3/payments/{id}` с ключом магазина |
| **Т-Банк / Т-Касса** (API v2) | Уведомление на `/api/payments/tbank/webhook` с подписью Token (SHA-256 с паролем терминала); неверная подпись — отказ. Дополнительно — `GetState` при возврате пользователя |

- Цена и количество токенов берутся только из тарифа на сервере; сумма из ответа банка сверяется с заказом.
- Токены зачисляются один раз (переход заказа `pending → paid`), повторные уведомления ничего не добавляют.
- После возврата на `/cabinet?order=…` кабинет показывает статус заказа и обновляет баланс.
- Чеки 54-ФЗ: в админке включается передача данных для чека (система налогообложения, ставка НДС); если у пользователя нет почты, кабинет попросит её перед оплатой.
- Настройка — админка → «Оплата»: shopId и секретный ключ ЮKassa, TerminalKey и пароль Т-Банка, пошаговая справка и адреса уведомлений. Для проверки — тестовый магазин ЮKassa и тестовый терминал Т-Банка (`…DEMO`).
- Журнал платежей — там же. Вручную баланс меняется в разделе «Пользователи».

## Админка — `/admin`

Сводка (пользователи, задачи, очередь, ошибки, расход токенов), пользователи (поиск, баланс с комментарием, роль, блокировка), тарифы, цены и бонусы, интеграции со справкой, последние задачи.

Администратор создаётся на сервере командой (пароль — только через переменную окружения):

```bash
cd /opt/creator-studio/api && CS_PASSWORD='…' node cli.mjs create-user --email admin@example.ru --name "Имя" --role admin
```

## Что не сделано

- Возвраты денег (refund) через API платёжных систем — пока вручную в их кабинетах, с последующим списанием токенов в админке.
- Подтверждение почты и восстановление пароля по почте (нужен почтовый сервис).
- Ключи Яндекса, VK, Telegram и MAX ещё не заведены — способы входа включатся после заполнения в админке.
