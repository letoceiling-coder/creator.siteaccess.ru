# Поведение экранов

Компоненты Helios переиспользуются как есть: кнопки, поля, карточки, диалог, вкладки, тосты, прогресс, пустое состояние, скелет. Новых визуальных токенов эта фаза не вводит. Интерактив не ниже 44 px. На 320 px нет горизонтальной прокрутки страницы; галереи примеров прокручиваются внутри своей полосы.

Тексты ниже — смысл, не финальный копирайт.

## Главная

Назначение: объяснить студию и вести в первую фотосессию.

Порядок блоков на телефоне, сверху вниз:

1. Hero. Крупный заголовок, одна фраза, главное действие «Выбрать фотосессию», второе «Смотреть видеосценарии». Фон — кадр из подготовленной галереи, не результат пользователя.
2. Короткая демонстрация: три работы «было фото — стал кадр». Это примеры студии.
3. Популярные фотосессии, горизонтальная лента карточек.
4. Популярные видео, лента с обложкой и длительностью. Если запуск видео ещё закрыт, карточка открывает описание и помечает «Скоро», без кнопки генерации.
5. Как это работает: выбрать сценарий, добавить фото, подтвердить, забрать результат.
6. Преимущества: готовые сценарии, без промптов, результат хранится в кабинете, можно закрыть приложение и вернуться.
7. Призыв создать первую работу.
8. Вопросы и ответы. В ответе про сходство нет обещания 100%. В ответе про срок сказано, что это оценка очереди.
9. Футер браузера: о сервисе, конфиденциальность, поддержка.

На широком экране hero занимает два столбца: текст и кадр. Ленты становятся сеткой.

Состояния: скелет лент, ошибка загрузки каталога с повтором, пустой каталог не показывается как поломка сервиса.

## Каталог фотосессий

Сверху заголовок и поиск по названию. Под ним горизонтальные категории. Дальше сетка: одна колонка на 320 px, две с 768 px, три с 1280 px.

Карточка: обложка с фиксированной пропорцией 3:4, название, категория, число кадров. Нажатие открывает карточку сценария. Категория фильтрует без перезагрузки всего приложения.

Состояния: загрузка скелетом, пустой фильтр «В этой категории пока нет сценариев», ошибка сети.

## Карточка фотосессии

1. Обложка на всю ширину телефона.
2. Галерея примеров: несколько кадров, разные позы и ракурсы, горизонтальная лента.
3. Название, категория, описание образа.
4. Одежда и что в ней можно сменить, если сценарий это разрешает.
5. Сколько кадров будет на выходе и какой формат.
6. Какие фото нужны.
7. Как сохраняется внешность простым языком: «Берём ваши фотографии как образец лица. Сходство зависит от качества снимков».
8. Оценка времени.
9. Стоимость только после утверждения тарифа.
10. Закреплённая кнопка «Создать».

Промпт, имя модели и шаги не выводятся.

## Каталог и карточка видео

Каталог устроен так же. На карточке вместо галереи фото — постер и пример ролика, если файл примера есть. Раскадровка — вертикальный список сцен: номер, что видит человек, откуда камера. Для погони в Дубае это салон, лицо, переход на машину, улицы, бок, задний план, верх, манёвр, финал.

Кнопка «Создать» на видео скрыта, пока этот тип не включён в запущенную версию. Вместо неё текст, что сюжет уже в каталоге, а запуск откроется отдельно.

## Создание

Один шаг на экран. Сверху короткий прогресс: Фото, Образ, Проверка. Назад сохраняет черновик.

### Фотографии

- Область drag-and-drop в браузере и кнопка «Выбрать с телефона» везде.
- Сетка выбранных кадров, у каждого удаление и замена.
- Формат, размер и число проверяются до отправки на генерацию. Правила лимитов — предлагаемые, сервером не подтверждены: JPEG, PNG или WebP, до 15 МБ файл, длинная сторона до 4096 px, от 1 до 3 файлов в MVP.
- Подсказки: лицо видно, без сильного фильтра, без сильного размытия, со светом, лицо не перекрыто, лучше два-три ракурса.
- Проверка пригодности в MVP — эти правила файла и подсказка человеку. Отдельная модель, которая «одобряет лицо», не заявляется: на сервере скрипты лица есть только у аватара, к этому продукту они не подключены.

Состояния: пусто, файл не принят с причиной, отправка на хранение, ошибка загрузки, готово к следующему шагу.

### Образ

Поля зависят от сценария.

- Египет: время суток и одно пожелание, без марки машины.
- Автомобильная погоня: цвет и тип машины из короткого списка сценария, без настроек одежды пустыни.
- Общие, если сценарий разрешил: одежда из 2–4 вариантов шаблона, атмосфера, время суток, одна строка пожелания до 200 знаков, формат кадра.

Значения по умолчанию приходят из сценария. Пустая строка пожелания допустима. Свободный промпт на весь кадр не предлагается.

### Проверка

Сводка: сценарий, миниатюры фото, выбранный образ, число результатов, предупреждения, стоимость при наличии. Одна главная кнопка «Подтвердить создание». Вторая — «Вернуться». Пока запрос подтверждения идёт, главная кнопка в состоянии загрузки и не шлёт второй запрос.

## Задача

Крупный статус человеческим языком.

| Код | Текст |
| --- | --- |
| `draft` | Черновик сохранён |
| `uploading` | Загружаем фотографии |
| `validating` | Проверяем файлы |
| `pending` | Задание принято |
| `queued` | В очереди |
| `processing` | Собираем кадры |
| `post_processing` | Готовим файлы |
| `completed` | Готово |
| `failed` | Не получилось |
| `cancelled` | Отменено |

Рядом оценка, не таймер-обещание: «Обычно такие кадры занимают очередь. Можно закрыть страницу». Прогресс-бар движется по статусу, не по проценту GPU: процента сервер не отдаёт. Кнопка отмены ведёт себя по правилам `USER_FLOWS.md`.

Потеря сети не сбрасывает экран в ошибку генерации.

## Результат

Сетка кадров с фиксированными пропорциями. Просмотр одного кадра на весь экран. Скачать один файл и скачать все. На видео позже — плеер и скачивание ролика. Удаление через диалог. «Собрать снова» открывает новый черновик.

Чужой идентификатор показывает не содержимое, а состояние «Работа не найдена».

## Кабинет

Обзор: последняя задача и кнопка в каталог. Остальные разделы — списки карточек. Пустые состояния объясняют следующий шаг. Профиль хранит имя и способ входа. Настройки: тема уже умеет переключаться в каркасе, сюда позже переедет то же действие и уведомления. Баланс не рисуется, пока тариф не утверждён.

## Загрузка и ошибки по всему продукту

Первый заход в раздел показывает скелет заранее известной высоты. Ошибка раздела — сообщение и «Повторить», без сброса темы и платформы. Тост используется для короткого итога вроде «Фото удалено», не для провала генерации.
