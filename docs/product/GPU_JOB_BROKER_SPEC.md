# Спецификация GPU Job Broker

Это проект нового процесса. На сервере он не создаётся и в этой фазе не включается. Свободная VRAM сама по себе владельцем карты не считается: модель может занимать память при нулевой утилизации, как `qwen3.6-128k` в снимке 17 ноября 2026.

## 1. Архитектура

Один брокер на хост. Клиент продукта и чужие сайты не ставят граф в ComfyUI напрямую.

```text
API продукта
  → запись задачи
  → брокер
      → исключительная аренда GPU
      → один граф в ComfyUI
      → чтение history и файла
      → снятие аренды
```

Студия, аватар и музыка сегодня ходят в тот же ComfyUI своими процессами и перед работой вызывают `freeVram`. Брокер обязан это учитывать: чужой `POST /prompt` может прийти, пока аренда «свободна» только по памяти. Поэтому аренда — отдельный замок, а не порог мегабайтов.

Пока чужие приложения не переведены на тот же замок, брокер не стартует прогон, если `nvidia-smi` показывает посторонний compute-процесс больше 2 ГиБ или очередь ComfyUI не пуста. Выгружать этот процесс брокер сам не имеет права, пока владелец хоста не разрешит тот же приём `freeVram`, которым уже пользуются соседи.

## 2. Блокировка GPU

Замок один на устройство `cuda:0`.

Предлагаемая реализация — файл аренды на локальном диске и `flock`. В файле: `holder`, `jobId`, `pid`, `acquiredAt`, `expiresAt`. Взять аренду может только тот, кто держит flock. Проверка «память свободна» без flock не выдаёт право запуска.

Аренда не выдаётся, если:

- flock уже занят
- в `nvidia-smi` есть чужой процесс больше 2 ГиБ
- `GET /queue` показывает `queue_running` или `queue_pending`
- срок прошлой аренды не истекает и держатель жив

Чужой процесс не убивается. Брокер ждёт или возвращает задачу в очередь.

## 3. Очередь

Очередь продукта хранится в его базе, не в очереди ComfyUI. В ComfyUI лежит не больше одного своего prompt.

Порядок FIFO среди задач продукта. Чужие сервисы брокер не обгоняет: если карта занята ими, продукт ждёт. Приоритет между продуктом и студией, аватаром, музыкой всё ещё не утверждён.

Повторное подтверждение с тем же ключом идемпотентности не ставит второй элемент очереди.

## 4. Статусы

Те же, что в архитектуре генерации: `draft`, `uploading`, `validating`, `pending`, `queued`, `processing`, `post_processing`, `completed`, `failed`, `cancelled`.

`queued` означает «аренды ещё нет». `processing` начинается только после успешного flock и пустой чужой очереди. `post_processing` — файл уже есть, идёт миниатюра или склейка, аренду GPU можно отпустить до миниатюры, если она считается на CPU.

## 5. Ошибки

- Нет аренды за отведённое ожидание — задача остаётся `queued`, это не `failed`.
- ComfyUI вернул ошибку prompt — `failed`, аренда снимается.
- Пропал ответ history дольше таймаута — один повтор того же графа, если частичного файла нет. Второй сбой — `failed`.
- Таймаут студии сегодня в коде: `max(eta * 4, eta + 180)` секунд, затем удаление prompt и `POST /interrupt`, если этот prompt уже бежит. Для брокера число берётся из измеренного eta, не из догадки. Пока свежего замера Edit нет, таймаут не фиксируется.
- `interrupt` брокер шлёт только для своего `prompt_id`. Чужой running prompt не прерывается.

## 6. Освобождение ресурсов

После `completed`, `failed` или `cancelled` брокер снимает flock. `POST /free` вызывается только если этот прогон сам грузил веса и владелец хоста разрешил тот же приём, что у студии. В обычном ожидании брокер чужую VRAM не трогает.

Временный вход ComfyUI (`/upload/image`) и свой выход удаляются политикой хранения продукта, не командой на чужие каталоги.

## 7. Защита от конфликтов

- Один flock на GPU.
- Один prompt продукта в ComfyUI.
- Не стартовать при чужом процессе в `nvidia-smi`.
- Не вызывать `keep_alive: 0`, `/unload` и `/free`, пока это не разрешено отдельно.
- Идемпотентность подтверждения.
- Отмена до `processing` снимает очередь продукта и не шлёт interrupt.
- Падение брокера: аренда с мёртвым pid и истёкшим `expiresAt` считается брошенной. Следующий старт её забирает только после проверки, что prompt этого `jobId` уже не в `queue_running`.

## 8. Несколько GPU

Устройство — отдельный исполнитель со своим flock: `cuda:0`, `cuda:1`. Задача не привязана к номеру карты, пока не взята аренда. Выбор карты: первая, где замок свободен и нет чужого тяжёлого процесса. Если все заняты, задача остаётся `queued`.

Контракт API продукта не меняется. Клиент не выбирает номер GPU.
