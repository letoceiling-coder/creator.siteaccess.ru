# Архитектура генерации

Документ разделяет подтверждённый снимок сервера от 17 ноября 2026 и предлагаемую обвязку продукта. Повторно на сервер эта фаза не выходила.

## Что подтверждено

Одна NVIDIA RTX 4090 24 ГиБ на общем хосте. Локальные фото и видео считает один ComfyUI на `127.0.0.1:8188`. Снаружи этот порт не опубликован. Перед тяжёлой задачей соседние приложения освобождают память: Ollama с `keep_alive: 0`, Chatterbox `POST /unload`, ComfyUI `POST /free`.

Для фото на диске есть Z-Image Turbo, Qwen-Image 2512 в быстром и долгом режиме, Qwen-Image-Edit 2511 с одним–тремя референсами и быстрым или долгим проходом, а также апскейл ESRGAN. Папки ControlNet, IP-Adapter и embeddings пустые.

Для видео есть Wan 2.2: текст или стартовый кадр, куски около 5 секунд, склейка, 1080p как 720p плюс увеличение и при необходимости RIFE. Отдельно живут говорящие аватары и LatentSync, им нужна почти вся карта, их этот продукт в MVP не использует.

Очередь самого ComfyUI и HTTP-методы постановки графа, кроме `POST /free`, в отчёте аудита не расписаны. Считать конкретный путь `/prompt` подтверждённым нельзя.

## Как продукт должен встать рядом

Новый сервис не рисует в интерфейсе студии `studio.siteaccess.ru` и не делит с ней чужие файлы. У него свой контур задач и свой каталог файлов. Общий только GPU и уже установленный ComfyUI.

```text
Клиент
  → API продукта, которого пока нет
    → запись задачи и проверка файлов
    → брокер видеокарты
      → освободить чужие веса, если это уже принятый на хосте приём
      → один граф в ComfyUI
      → дождаться результата
      → ffmpeg или ESRGAN, если шаг нужен
      → записать файлы и метаданные
    → клиент читает статус и скачивает
```

Брокер — предлагаемая часть. Его нет в репозитории.

Пока брокер не уверен, что карта свободна от чужого тяжёлого прогона, новый прогон не стартует. Задача остаётся в `queued`. Несколько тяжёлых графов параллельно не запускаются. Вторая видеокарта в схеме предусмотрена как будущий исполнитель с тем же контрактом задачи, без смены экранов.

## Какой граф предлагается для MVP

Только фотосессия.

Предлагаемый путь сходства: Qwen-Image-Edit 2511 Fast, 1–3 фотографии человека как референсы, скрытый текст сценария на сервере, 4 шага. Долгий режим Edit на 40 шагов в MVP не включается. Z-Image и Qwen без референса для «это я» не используются: они не привязаны к лицу так же, как Edit.

Это предложение, не включённый пайплайн. Качество сходства на этих весах для каталога студии ещё не измерялось.

Апскейл ESRGAN подключается только если кадр меньше обещанного размера. По умолчанию обещать 4K нельзя, пока не измерен расход памяти.

## Видео, когда до него дойдёт очередь

Один кадр сценария — отдельный прогон Wan 2.2 от стартового изображения, около 5 секунд. Ролик длиннее 5 секунд режется на такие куски и склеивается ffmpeg, это поведение уже есть у текущей студии. Сценарий из девяти сцен — девять тяжёлых прогонов строго по одному.

Оценка времени для человека складывается из очереди и суммы прогонов. Длительность ролика сама по себе цену и срок не определяет: 5 секунд в 1080p с увеличением и RIFE тяжелее 5 секунд в 720p.

Согласованность лица между сценами опирается на одни и те же референсы. Отдельного подтверждённого замка лица нет. Поэтому видео не входит в MVP.

Оживление готового фото — другой режим: движение внутри одного снимка, без новой локации. Его тоже нет в первом запуске.

Коллаж собирается из готовых файлов на CPU, без ComfyUI.

## Статусы

| Статус | Когда |
| --- | --- |
| `draft` | Задача создана, генерации нет |
| `uploading` | Файлы ещё едут |
| `validating` | Проверяются тип, размер и число |
| `pending` | Подтверждена, брокер ещё не смотрел карту |
| `queued` | Ждёт свободную карту |
| `processing` | Идёт один граф |
| `post_processing` | Склейка, масштаб, превью |
| `completed` | Файлы можно скачать |
| `failed` | Прогон или проверка не удались |
| `cancelled` | Человек отменил до необратимого прогона |

Переходы вперёд только по этому списку, кроме `failed` и `cancelled`, которые можно поставить из `pending`, `queued` и, для сбоя, из `processing` и `post_processing`. Из `completed` назад задача не ходит.

## Надёжность

- Идентификатор задачи — UUID, его создаёт сервер.
- Подтверждение несёт ключ идемпотентности. Повтор той же команды возвращает ту же задачу.
- Повторная выдача результата читает уже записанные файлы и не ставит новый прогон.
- Обрыв клиента не отменяет `processing`.
- Таймаут прогона задаётся брокером. Число минут аудитом не подтверждено, его нужно снять на одном реальном кадре до публичного запуска.
- Автоматический повтор после сбоя GPU — не больше одного раза и только если прогон не записал частичный результат. Иначе человек видит `failed`.
- Отмена во время `processing` в MVP не обещается: способ остановить уже взятый ComfyUI в аудите не зафиксирован.

## Что нельзя проектировать как факт

Мгновенную генерацию, параллельные видео, обучение LoRA на пользователя, FaceID, IP-Adapter, ControlNet, готовую очередь Redis и публичный API текущей студии. Этого в подтверждённом контуре продукта нет.
