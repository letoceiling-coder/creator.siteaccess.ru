# Тестирование

Готовым считается изменение, у которого прошли нужные проверки, а не только сборка.

## Unit и компоненты

```bash
npm run test
```

Vitest и Testing Library. Окружение jsdom. Настройка — `src/test/setup.ts`. В прогон входят только `src/**/*.test.ts` и `src/**/*.test.tsx`.

Сейчас покрыто:

- слияние классов `cn`;
- схема имени и резолвер React Hook Form;
- определение Telegram, MAX, предпросмотра и кнопки «назад» хоста;
- имя и состояние загрузки кнопки;
- контраст палитры, совпадение hex с CSS и длительности движения.

Логику платформы проверять через `readPlatformSnapshot`, без поднятия всего приложения.

## E2E

```bash
npx playwright install chromium
npm run test:e2e
```

Playwright поднимает `npm run dev` на `127.0.0.1:5173`. Проекты Chromium: `mobile-320`, `mobile-390`, `tablet-768`, `desktop-1280`, `wide-1536`. WebKit на этой машине не входит в обязательный прогон: на Windows он тяжёлый и не нужен, чтобы поймать переполнение и axe. Для отдельной проверки iOS WebView его можно добавить позже.

`e2e/foundation.e2e.ts` открывает стенд, проверяет ошибку поля, закрытие диалога по Escape, отсутствие горизонтального переполнения, serious/critical нарушения axe и ошибки консоли. На desktop дополнительно открывает стенд с `prefers-reduced-motion`.

`e2e/shell.e2e.ts` на 390 и 1280 проходит `/`, `/telegram`, `/max` и неизвестный путь. На desktop переключает тему.

Файлы называются `*.e2e.ts`, чтобы Vitest их не забрал.

## Доступность

Автоматически закрыта часть WCAG: роли, имена, контраст токенов, диалог, axe на стенде. Это не вся WCAG 2.2. Клавиатурный обход нового экрана и смысл текста по-прежнему смотреть вручную. Ориентир — уровень AA.

## Что запускать

| Изменение            | Команды                              |
| -------------------- | ------------------------------------ |
| Функция или тип      | `typecheck`, `lint`, `test`          |
| Компонент или экран  | то же, `build`, `test:e2e`           |
| Токены               | `test` и просмотр обеих тем          |
| Зависимость или Vite | `typecheck`, `lint`, `test`, `build` |

`format:check` уместен перед сдачей любой пачки файлов.

В отчёте писать фактический итог. Пропущенную команду не отмечать как пройденную.
