# react-architecture

## Назначение

Чтобы новый код попадал в понятное место и не тащил за собой лишний каркас. Архитектура остаётся плоской, пока домен не появился.

## Когда применять

Новый маршрут, компонент, хук, провайдер, перенос файла, решение «куда положить состояние».

## Область

```text
src/app          провайдеры, тема, роутер
src/pages        сборка конкретного экрана
src/features     домен с логикой; сейчас это platform
src/components   переиспользуемый UI и каркас
src/shared       чистые функции без React
src/hooks        общие хуки без домена
src/config       токены для TS
src/styles       глобальные токены
src/types        общие типы, если им тесно в модуле
```

Пустые каталоги не создавать. `assets` появляется вместе с первым файлом.

## Инструкции

1. Посмотреть, нет ли уже компонента или функции с этой ролью.
2. Экран собирается в `pages` из компонентов. Запрос к хосту и определение платформы не писать внутри страницы — это `features/platform`.
3. Общий UI без знания продукта класть в `components/ui`. Каркас приложения — в `components/layout`.
4. Состояние экрана оставлять в экране (`useState`). Состояние темы, тостов и платформы уже есть в провайдерах. Новый глобальный стор не добавлять, пока нет нескольких далёких потребителей одних и тех же сложных данных.
5. Именованный экспорт. Динамический импорт страницы возвращает этот экспорт через `.then`, как `FoundationPage`.
6. Тип импортировать отдельно. Индекс доступа проверять: `noUncheckedIndexedAccess` включён.
7. Файл компонента не экспортирует хук рядом с компонентом: хук живёт в своём файле (`use-toast.ts`, `use-platform.ts`). Так Oxlint не смешивает публичный API.
8. Алиас `@/` указывает на `src`. Импорт заканчивается на `.ts` или `.tsx`.

## Правила

- Страница не импортирует чужую страницу.
- Компонент UI не импортирует страницу и не знает про маршрут, кроме каркаса, которому положено знать.
- Провайдер оборачивает дерево в `src/app/providers.tsx`. Порядок: тема, роутер, платформа, тосты. Тосты зависят от платформы, поэтому стоят внутри неё.
- Форма будущего продукта использует `displayNameSchema` как образец связки Zod и React Hook Form, а не новую библиотеку валидации.

## Запрещено

- Слой repository/use-case/presenter для одного компонента.
- Копия приложения под Telegram и под MAX.
- `any` вместо узкого типа хоста.
- Default export у компонента, который импортируется статически.
- Циклический импорт между `app` и `components`. Каркас может импортировать хук темы из `app`, но `app` не должен тянуть каркас через страницу и обратно в провайдер.

## Критерии качества

- Назначение файла понятно по пути.
- Компонент можно прочитать без прокрутки на много экранов. Сборка страницы длиннее атомарного контрола — это нормально, пока секции не начинают жить своей логикой. Такую секцию выносить.
- `npm run typecheck` проходит со strict.

## Пример

Платформа читается чистой функцией и тестируется без браузера:

```ts
const snapshot = readPlatformSnapshot({ innerHeight: 500 }, '/telegram')
snapshot.id // 'telegram'
snapshot.sdkReady // false, пока нет window.Telegram.WebApp
```

- [ ] Место файла совпадает с правилами каталогов.
- [ ] Нет дубля существующего компонента.
- [ ] Типы явные, `import type` на месте.
- [ ] Состояние поднято не выше нужного потребителя.
- [ ] `npm run typecheck` выполнен после структурной правки.
