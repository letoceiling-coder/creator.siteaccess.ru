# frontend-testing

## Назначение

Сборка не считается готовностью. Проверка подтверждает тип, стиль кода, поведение модуля и сценарий в браузере.

## Когда применять

После изменения логики, компонента, стиля токенов, маршрута или конфигурации качества. Перед утверждением, что задача готова.

## Область

- `npm run typecheck` — `tsc -b`, strict.
- `npm run lint` — Oxlint с type-aware правилами. ESLint в проект не добавлять: шаблон Vite 8 использует Oxlint, второй линтер дублирует работу и плохо стыкуется с TypeScript 7.
- `npm run format:check` — Prettier.
- `npm run test` — Vitest, jsdom, Testing Library. Файлы `src/**/*.test.ts(x)`.
- `npm run test:e2e` — Playwright, Chromium, проекты 320, 390, 768, 1280, 1536. Перед первым запуском: `npx playwright install chromium`.
- axe-core через `@axe-core/playwright` на стенде. Контраст палитры — отдельный unit-тест, чтобы токены не разъехались с CSS.

## Инструкции

1. Чистую функцию (платформа, контраст, схема) тестировать без рендера.
2. Компонент рендерить через Testing Library и искать роль и имя, не класс.
3. Сценарий маршрута, клавишу Escape, переполнение и axe писать в `e2e/*.e2e.ts`. Имя `*.e2e.ts` не подхватывается Vitest.
4. Ошибки `pageerror` и `console` типа `error` на проверенном сценарии должны остаться пустыми.
5. Новый экран добавлять в e2e хотя бы проверкой заголовка и `scrollWidth`.
6. Не ставить `test.only`. В CI повтор e2e включён конфигом.
7. Запускать команды самому и в отчёте писать фактический результат. Не выдумывать зелёный прогон.
8. Если проверка не запускалась (нет браузера, нет сети), так и написать.

## Правила

- Тест падает на поломке продукта, а не на порядке классов.
- Исправление теста ради красного axe без правки интерфейса запрещено.
- Снапшот всего HTML не использовать.
- Хук и провайдер, которые трудно отрисовать, опираются на чистую функцию рядом. Так устроена платформа: тестируется `readPlatformSnapshot`.

## Запрещено

- Считать `npm run build` единственной проверкой.
- Отключать strict, чтобы тест собрался.
- Живой запрос к AI, оплате или чужому SDK из теста.
- Пустой тест-заглушка.

## Критерии качества

- Покрыта новая ветка логики, а не только счастливый рендер.
- e2e смотрит тот вьюпорт, который правка могла сломать.
- В отчёте есть команды и итог, включая пропущенные.

## Пример

```ts
const snapshot = readPlatformSnapshot({ innerHeight: 800, WebApp: host }, '/')
expect(snapshot.id).toBe('max')
expect(snapshot.sdkReady).toBe(true)
```
