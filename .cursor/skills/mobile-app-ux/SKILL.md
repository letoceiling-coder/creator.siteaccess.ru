# mobile-app-ux

## Назначение

Один интерфейс ощущается уместно в обычном браузере, в Telegram WebView и в MAX WebView. Бизнес-логика не знает, какой контейнер её открыл.

## Когда применять

Оболочка, нижняя зона, safe area, кнопка «назад» хоста, клавиатура, жест, сенсорная цель, определение окружения.

## Область

Маршруты входа: `/` браузер, `/telegram` Telegram, `/max` MAX. Реальный хост важнее маршрута. Определение и адаптеры: `src/features/platform`. Каркас: `src/components/layout/app-frame.tsx`.

Telegram узнаётся по `window.Telegram.WebApp` с `ready` и `close`. MAX — по `window.WebApp`, если есть `deviceName` или `downloadFile`, и только когда это не Telegram. Оба глобальных объекта описаны узкими типами в `types.ts`. SDK скриптом не подключать, пока нет отдельного задания на интеграцию.

## Инструкции

1. Новое поведение хоста добавлять методом адаптера (`signalReady`, `close`, `bindBack`, insets, viewport), затем вызывать его из UI.
2. Если SDK нет, метод ничего не делает и экран честно показывает «SDK не подключён». Маршрут `/telegram` и `/max` в обычном браузере — предпросмотр зоны, не имитация пользователя.
3. Safe area в вёрстке всегда через `env(safe-area-inset-*)`. Числа из Telegram `contentSafeAreaInset` показывать и учитывать, когда они есть. У MAX на этом этапе числа зоны берёт CSS, потому что мост отдаёт viewport отдельным промисом и ещё не подключён.
4. Нижняя панель мини-приложения включается флагом `reservesNavigationInset`. Контент получает нижний padding, тосты поднимаются над панелью.
5. Системную «Назад» вешать через `adapter.bindBack` и снимать в cleanup. Не рисовать вторую стрелку, если хост уже показывает свою.
6. Цель касания не меньше 44px. Между соседними целями оставлять зазор, чтобы промах не нажимал соседнее.
7. Поле у нижнего края можно доскроллить, когда `visualViewport` сжимается клавиатурой.
8. Жест не обязателен для действия. Всё, что делается свайпом, делается и кнопкой.

## Правила

- Не ветвить продуктовый экран по `if (telegram)` больше одного раза. Ветка живёт в адаптере.
- Не копировать дерево компонентов под платформу.
- `ready()` вызывать из эффекта провайдера, не из рендера.
- Закрытие мини-приложения — только по явному действию и только через адаптер.

## Запрещено

- Пакет `max-web-app`, Telegram WebApp script или `@twa-dev/sdk`, пока интеграция не запрошена.
- Чтение `initData` для авторизации на клиенте. Подпись проверяется на сервере, сервера в этой фазе нет.
- `requestContact`, оплата и скачивание файлов из адаптера-заготовки.
- Фиксированная панель без учёта safe area и клавиатуры.

## Критерии качества

- Три маршрута открывают одну оболочку и разный ярлык платформы.
- В браузере нет ложной нижней панели.
- В предпросмотре мини-приложения панель не перекрывает последнее действие.
- Контракт адаптера покрыт тестом `snapshot.test.ts`.

## Пример

```ts
const snapshot = readPlatformSnapshot(window, location.pathname)
snapshot.adapter.signalReady()
const release = snapshot.adapter.bindBack(() => navigate(-1))
return release
```

## Чек-лист

- [ ] UI не трогает `window.Telegram` и `window.WebApp` напрямую.
- [ ] Предпросмотр без SDK не притворяется подключённым хостом.
- [ ] Safe area и нижняя зона не перекрывают контент.
- [ ] Цели касания ≥ 44px.
- [ ] Есть способ выполнить действие без жеста.
