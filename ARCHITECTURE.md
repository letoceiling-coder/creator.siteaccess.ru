# Архитектура

## Поток запуска

`index.html` ставит `data-theme` до первой отрисовки. `src/main.tsx` подключает шрифты и глобальные стили и монтирует `App`. Провайдеры идут в порядке: тема, `BrowserRouter`, платформа, тосты. Тосты стоят внутри платформы, потому что отступ снизу зависит от нижней зоны мини-приложения.

Каркас `AppFrame` — родительский маршрут. Страницы рисуются в `<Outlet />`. Стенд подгружается через `lazy`, каркас при этом остаётся, а запасной блок имеет высоту.

## Каталоги

| Путь                    | Ответственность                                |
| ----------------------- | ---------------------------------------------- |
| `src/app`               | Сборка приложения, тема, таблица маршрутов     |
| `src/pages`             | Оболочка и стенд. Без доменной логики хоста    |
| `src/features/platform` | Сигналы окружения и адаптеры                   |
| `src/components/ui`     | Контролы без знания маршрута                   |
| `src/components/layout` | Каркас, safe area, шапка, нижняя зона          |
| `src/shared`            | Функции без React                              |
| `src/hooks`             | Общие подписки браузера                        |
| `src/config`            | Значения, которые нужны и TypeScript, и тестам |
| `src/styles`            | Токены и глобальные правила                    |

Новый домен добавляется папкой в `features`, когда появляется логика, а не только разметка. Пустые папки не заводить.

## Маршруты и платформы

Одна кодовая база.

| Путь              | Роль                                 |
| ----------------- | ------------------------------------ |
| `/`               | Вход браузера                        |
| `/telegram`       | Вход Telegram и предпросмотр без SDK |
| `/max`            | Вход MAX и предпросмотр без SDK      |
| `/dev/foundation` | Стенд, доступен из любой платформы   |

`readPlatformSnapshot` решает так:

1. Есть `window.Telegram.WebApp` с `ready` и `close` — Telegram, даже если открыт другой путь.
2. Иначе есть `window.WebApp` с `deviceName` или `downloadFile` — MAX.
3. Иначе путь `/telegram` или `/max` — предпросмотр, `sdkReady` ложен.
4. Иначе браузер.

UI вызывает `adapter.signalReady`, `adapter.close` и `adapter.bindBack`. Прямых обращений к хосту в компонентах нет.

SDK не подключён. `signalReady` и `close` ничего не делают, пока объекта хоста нет. У Telegram insets читаются из `contentSafeAreaInset`, затем из `safeAreaInset`. У MAX размер viewport в мосте асинхронный (`getViewportSize`); пока SDK не подключён, высота берётся из окна, а безопасные поля — из CSS `env(safe-area-inset-*)`. Это граница фазы, не забытый вызов.

Авторизацию по `initData` делать на сервере. Клиент эти строки для доверия не использует.

`BrowserRouter` требует, чтобы хостинг отдавал `index.html` на неизвестные пути. `vite dev` и `vite preview` это умеют.

## Состояние

Локальный `useState` на экране. Тема, платформа и очередь тостов — три небольших контекста. Отдельного стора нет: нечего синхронизировать между далёкими частями дерева.

## Стили

Tailwind 4 читает `@theme inline` из `src/styles/global.css`. Компоненты пользуются утилитами. Произвольные цвета в классах не добавлять.

## Что не входит в основу

Генерация, аккаунт, оплата, сеть, состояние сервера, реальные скрипты Telegram и MAX.
