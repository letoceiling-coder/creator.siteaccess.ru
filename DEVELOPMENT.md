# Разработка

## Подготовка

```bash
npm install
npm run dev
```

Сервер Vite открывает приложение на `http://127.0.0.1:5173`. Для e2e один раз установить браузер:

```bash
npx playwright install chromium
```

Проверено на Node.js 24.16 и npm 11.13. pnpm в системе тоже есть, но lockfile проекта — npm. Смешивать менеджеры не нужно.

## Повседневные проверки

```bash
npm run typecheck
npm run lint
npm run format:check
npm run test
npm run build
```

Oxlint включён с `typeAware`. Это линтер шаблона Vite 8 на TypeScript 7. ESLint рядом не ставится.

Форматирование исправляется командой `npm run format`.

## Как добавить компонент

1. Найти близкий контрол в `src/components/ui`. Расширять его, если отличие — вариант, а не новая роль.
2. Новый файл называть строчными словами через дефис. Компонент экспортировать по имени.
3. Стили брать из токенов в `DESIGN_SYSTEM.md`.
4. Показать контрол на стенде `/dev/foundation`.
5. Для логики без UI добавить тест рядом с файлом: `имя.test.ts`.

Импорт:

```ts
import { Button } from '@/components/ui/button.tsx'
```

## Как добавить экран

Экран — файл в `src/pages` и маршрут внутри `AppFrame` в `src/app/router.tsx`. Тяжёлую страницу подключать через `lazy`, чтобы она не попала в начальный чанк. Оболочку не копировать.

Пока нет задания на продукт, не заводить каталоги, кабинет и оплату.

## Мобильная проверка

В DevTools или в Playwright: 320, 390, 768, 1280, 1536. Отдельно открыть `/telegram` и `/max`: снизу должна быть зона хоста, контент не должен уходить под неё. В обычном `/` этой зоны нет.

Safe area на устройстве с вырезом работает, потому что во viewport указан `viewport-fit=cover`. В обычном desktop-браузере `env(safe-area-inset-*)` равен нулю, и оболочка показывает «CSS env()».

Клавиатуру можно имитировать уменьшением visual viewport. Высота на оболочке берётся из `useVisualViewport`.

## Ограничения

- Не подключать скрипты `telegram-web-app.js` и `max-web-app.js`, пока нет задачи на интеграцию.
- Не ставить GSAP, UI-кит, второй валидатор и второй линтер без причины, записанной в изменении.
- Не отключать `strict`, `noUncheckedIndexedAccess` и `erasableSyntaxOnly`.
- Git hooks не используются: проверки запускаются командами, а не скрытым pre-commit.
